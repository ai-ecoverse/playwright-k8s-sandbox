A restart is not a restore.

Reuse is common to all four. While a session is alive, the same playwright-id maps to the cached endpoint. An active WebSocket keeps that session from being reaped.

Idle reaping deletes, in all four adapters. The next request provisions a new sandbox. It does not automatically restore the previous browser session.

Substrate adds a separate suspend/resume path. An explicit memory-fidelity snapshot can preserve a suspended actor. The lifecycle exercise used this path rather than forced boot.

Where do agent-sandbox snapshots, sandboxd, and sandbox-router fit?

They are separate upstream options, not hidden steps in the direct-Pod path above. GKE Pod Snapshots provide checkpoint/restore, including a golden-snapshot warm-pool example. sandboxd provides process and filesystem APIs; sandbox-router forwards traffic to existing sandboxes. Neither component is itself the checkpoint engine.

Where does Google AX fit?

AX adds task, workspace, and model orchestration above substrate. It is not a fifth independent isolation runtime.
